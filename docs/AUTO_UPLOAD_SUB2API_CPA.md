# CPA 与 Sub2API

## CPA 导入

在账号页选择本地 CPA JSON，或配置 CPA 连接后选择远程凭证。仅接受明确标记为 `codex` 的 OAuth 文件；其他供应商、类型缺失或类型冲突的记录会跳过。

服务端会在远程列表和下载内容两处验证类型。本地 JSON 通过同一后端规则检查，不能靠修改页面绕过。

保留 `access_token`、`refresh_token`、`id_token`、`account_id`、邮箱及有效期字段；`codex` 表示凭证来源，不作为账号套餐。

结果分别列出新增、重复、类型不支持和失败。重复凭证不会覆盖已有记录；损坏的文件不会阻止其他文件导入。账号原有非 GPT 记录应由管理员核对后禁用或移除，业务调用不会使用它们。

## OAuth 导出与投递

账号页可导出 CPA 或 Sub2API 兼容格式，文件包含完整认证信息。仅将其导入可信服务，不把导出文件提交到 Git。

注册设置中的 CPA/Sub2API 投递以已有连接为目标；连接配置和注册执行器必须实际可用。同步失败应保留本地凭证，修复连接后再重试。

## 排查

- 列表为空：确认 CPA 文件为 Codex OAuth，管理连接有权限读取凭证列表。
- 类型不支持：检查 JSON 的 `type/provider`，不要将其他供应商文件强制改名后导入。
- 凭证过期：有 refresh token 时尝试刷新，无 refresh token 时重新获取有效授权。
- 大批量导入：查看分项结果并先处理失败记录，避免重复全量导入。
