# CPA 与 Sub2API

## 导入与凭证归属

CPA 仅接受明确标记为 `codex` 的 OAuth 文件，远程列表和下载内容都验证类型；Sub2API 仅接受 OpenAI OAuth 账号。本地 CPA JSON 使用相同的后端校验。

远程导入保存 `credential_owner`、`credential_source_id`、`credential_remote_id`，分别表示管理方、连接 ID 和远端文件名／账号 ID。保留 AT、ID token、工作区和有效期，不保留 RT；同一来源记录更新原账号，保留本地 ID、统计、分组、禁用设置及任务关联。

AT 临近到期、明确 `401` 或手动刷新时只向原渠道读取最新凭证。并发同步合并，迟到的结果不覆盖新凭证；渠道故障或仍返回失效凭证时退避等待，未过期 AT 可继续使用，过期后暂停。不会回退本地 RT 刷新、删除账号或自动换渠道；已接受或结果不明的图片请求不重新提交。

账号页显示“CPA 托管”“Sub2API 托管”及等待更新状态。导入结果列出新增、更新、重复、类型不支持和失败，损坏记录不阻止其他记录导入。

## 绑定历史账号

本地 CPA JSON 和未迁移的 Codex 记录标记为“外部来源待绑定”，本地轮换同样被禁止。先配置原渠道，再向管理接口 `POST /api/accounts/source` 提交：

```json
{
  "account_ref": "本地账号 ID",
  "credential_owner": "cpa",
  "credential_source_id": "连接 ID",
  "credential_remote_id": "原 CPA 文件名.json"
}
```

Sub2API 使用 `credential_owner: "sub2api"` 和原远端账号 ID。服务端下载并核对凭证及工作区后原位绑定；冲突返回 409，不按邮箱或工作区批量合并独立凭证。绑定前保护性备份，确认正确后移除活动记录中的旧 RT；不要恢复这些 RT 让两个服务重新竞争。

## 导出与投递

导出和备份含认证信息，只交给可信服务，不提交到 Git。外部托管账号的导出不包含 RT；本地 OAuth 账号仍由本项目管理。投递本地 RT 前先明确唯一管理方，不能让多个渠道同时轮换。

## 排查

- 列表为空或类型不支持：检查渠道权限及原始 `type/platform`，不要将其他供应商凭证强改为 Codex。
- 来源待绑定：配置原连接并绑定远端记录；导入文件本身不能提供自动同步渠道。
- 等待渠道更新：检查连接、远端记录及原渠道的刷新任务；本地不代刷 RT。
