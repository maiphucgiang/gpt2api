# 升级与回退

## 切换前

1. 在隔离目录运行测试、CI 构建和静态检查，保留当前镜像、二进制、Compose 文件与环境配置。
2. 暂停入口并排空在途请求和图片任务，再停止旧主服务。不要让两个实例写同一 JSON 数据目录。
3. 将 `data/`、配置、密钥和日志备份到项目外的私有目录；启用图片队列时还需一致性备份 Redis/AOF。
4. 记录当前端口、挂载绝对路径、容器 UID/GID、网络别名和代理设置。

## 配置迁移

- 使用 `cmd/gpt2api`、`bin/gpt2api`、`Dockerfile` 和根目录 `docker-compose.yml`。
- 新安装使用 `GPT2API_AUTH_KEY`、`GPT2API_ADMIN_KEY`、`GPT2API_WEBUI_KEY`；历史认证环境变量仍作为回退，新名称优先。
- 将旧部署的根目录、数据目录变量映射为 `GPT2API_ROOT_DIR`、`GPT2API_DATA_DIR`，启动前核对解析后的目录与原挂载一致。
- `GPT2API_DATA_DIR` 决定默认持久化路径；具体 `GO_*_PATH` 覆盖仍有效。已有 `data/config.json` 不被旧根目录配置覆盖。
- 数据结构保持兼容；旧数据中重复的账号引用会区分为独立 ID，保留上游工作区标识。成功／失败累计和 OAuth 凭证保留，不补算历史次数。
- 非 GPT 账号保留供管理员核对，不参与业务请求或后台配额检查。
- 浏览器登录存储键、文件签名与图片队列数据标识保持兼容，不因产品改名而重置。

## Docker 与服务名称

默认 Compose 项目名为 `gpt2api`，只启动 Go 主服务。启用图片队列需增加 `--profile images`，并保留 `data/go-image-redis/` 和既有鉴权文件。

图片网关仍只读取 `data/auth_keys.json`；该文件必须存在。更换该文件后重建网关容器，使绑定挂载读取新文件。

`docker-compose.go.yml` 为主 Compose 的兼容入口。服务器专用覆盖文件需要人工核对旧容器名、外部网络、端口和绝对挂载路径，不能直接套用新默认值。

systemd 与 launchd 模板改为直接启动 Go 二进制。修改目录前先停止旧服务并更新工作目录、反向代理和服务定义。

GitHub 仓库改名、Git 远端 URL、GHCR 包和服务器目录是独立操作。仓库改名不会自动迁移镜像包；这些步骤应在代码验证通过且获得发布授权后执行。

## 验收与回退

切换后检查：健康接口、管理员登录、匿名请求被拒绝、GPT 模型目录、配额自动刷新、调用计数、CPA 类型过滤、图片链接及队列任务。

若验收失败，停止新实例，恢复旧配置、挂载和镜像。需要恢复备份时先保留新产生的数据，再按已确认的时间点恢复；不要覆盖未备份的新账号或任务。
