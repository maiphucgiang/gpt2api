# 升级与回退

## 切换前

1. 在隔离目录运行测试、CI 构建和静态检查，保留当前镜像、二进制、Compose 文件与环境配置。
2. 暂停入口并排空在途请求和图片任务，再停止旧主服务。不要让两个实例写同一 JSON 数据目录。
3. 将 `data/`、配置、密钥和日志备份到项目外的私有目录；启用图片队列时还需一致性备份 Redis/AOF。
4. 记录当前端口、挂载绝对路径、容器 UID/GID、网络别名和代理设置。

## 配置迁移

- 使用 `cmd/gpt2api`、`bin/gpt2api`、`Dockerfile` 和根目录 `docker-compose.yml`。
- 新安装把 `config.example.json` 复制为 `data/config.json`（权限 `600`），填写 `auth-key`、`admin_key`、`webui_key`；不要覆盖已有 `data/config.json`。历史认证环境变量仍作为回退或显式覆盖，新名称优先。
- 将旧部署的根目录、数据目录变量映射为 `GPT2API_ROOT_DIR`、`GPT2API_DATA_DIR`，启动前核对解析后的目录与原挂载一致。
- `GPT2API_DATA_DIR` 决定默认持久化路径；具体 `GO_*_PATH` 覆盖仍有效。已有 `data/config.json` 不被旧根目录配置覆盖。
- 旧 `.env` 仍可供 Compose 插值宿主机端口、镜像、UID/GID、时区和网关/邮箱参数；应用运行字段改在 `data/config.json`。
- 数据结构保持兼容；旧数据中重复的账号引用会区分为独立 ID，保留工作区标识与调用累计，不补算历史次数。本地 OAuth 凭证保留；外部托管 RT 按下面的归属迁移步骤移除。
- 非 GPT 账号保留供管理员核对，不参与业务请求或后台配额检查。
- 浏览器登录存储键、文件签名与图片队列数据标识保持兼容，不因产品改名而重置。
- 新增 `data/image_tasks.json` 保存控制台图片任务；重启后保留历史，将未完成任务标记为中断，已记录会话的任务可续取，不自动重新生成。
- `/health` 新增 `image_tasks.pending/ready`；任务存储异常返回 503。内部调度接口必须设置密钥，空密钥不再放行。

## 凭证归属与订阅迁移

1. 升级期间暂时关闭旧版自动检查，记录原设置；一致性备份必须包含账号、渠道连接、任务与配置。
2. 逐条核对原渠道凭证，只有唯一且一致的匹配才能自动绑定；分叉或多重匹配需人工核对，独立 Web／OAuth 账号不按邮箱或工作区合并。
3. 写入 `credential_owner`、`credential_source_id`、`credential_remote_id` 后移除活动记录的 RT，保留本地 ID、统计和任务引用；也可使用 `/api/accounts/source` 校验后绑定。未绑定 Codex 记录默认禁止本地轮换。
4. 新版恢复自动检查，验证原渠道原位同步与失败退避。同步只更新凭证，不重新创建账号；确认没有本地 OAuth 轮换请求。

回退到没有归属保护的版本时必须保留渠道绑定和已移除 RT 的状态；不得恢复旧 RT 或旧账号备份。旧版不能自动向渠道同步，修复并升级前需人工维护到期凭证。

## Docker 与服务名称

默认 Compose 项目名为 `gpt2api`，只启动 Go 主服务。启用图片队列需增加 `--profile images`，并保留 `data/go-image-redis/` 和既有鉴权文件。

图片网关仍只读取 `data/auth_keys.json`；该文件必须存在。更换该文件后重建网关容器，使绑定挂载读取新文件。

本地构建改用完整的 `docker-compose.local.yml`（含 app 构建、图片网关、Redis、iCloud profile，默认端口 8000）。默认 `docker-compose.yml` 使用 `ghcr.io/maiphucgiang/gpt2api:latest`，不再本地构建 app。WARP 叠加文件为 `docker-compose.warp.yml`。服务器专用覆盖文件需要人工核对旧容器名、外部网络、端口和绝对挂载路径，不能直接套用新默认值。

systemd 与 launchd 模板改为直接启动 Go 二进制。修改目录前先停止旧服务并更新工作目录、反向代理和服务定义。

GitHub 仓库改名、Git 远端 URL、GHCR 包和服务器目录是独立操作。仓库改名不会自动迁移镜像包；这些步骤应在代码验证通过且获得发布授权后执行。

## 验收与回退

切换后检查：健康接口、管理员登录、匿名请求被拒绝、GPT 模型目录、配额自动刷新、调用计数、CPA 类型过滤、图片链接及队列任务。

若验收失败，停止新实例，恢复旧配置、挂载和镜像。需要恢复备份时先保留新产生的数据，再按已确认的时间点恢复；不要覆盖未备份的新账号或任务。

OAuth 新凭证一旦保存，回退程序也应保留它们；不要用旧备份直接覆盖已经轮换的 AT/RT。回退前留存 `image_tasks.json`，旧版不具备新任务续取能力。
