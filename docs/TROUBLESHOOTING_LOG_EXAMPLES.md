# 故障排查

## 基础检查

```bash
date -Is
docker compose ps
docker compose logs --tail 100 app
bash scripts/verify_live.sh http://127.0.0.1:3000
```

原生服务使用 `journalctl -u gpt2api -n 100 --no-pager`。共享诊断信息前遮盖 token、密钥、邮箱和代理凭证。

## 配额没有变化

- 先确认账号启用、自动检查开启，以及 `last_quota_refresh_at`、`next_run_at` 是否更新。
- 自动检查按配置间隔访问上游，页面的 10 秒刷新只读取本地状态。
- 上游临时错误会退避并保留旧配额；查看 `last_refresh_error`，不要把旧值当成刚刚确认的额度。
- 套餐没有返回明确图片上限时显示未知，不应解释为余额为零。

## 成功／失败计数

计数从有效业务调用反馈开始累计。后台配额检查不计数；重试换号时，失败属于原账号，成功属于实际完成的账号。客户端主动取消不作为账号故障。

正常关闭会刷新计数到磁盘；避免强制终止进程。若重启后丢失，先检查数据目录属主、磁盘空间和写入错误。

## CPA 导入

只接受 Codex OAuth。查看新增、重复、类型不支持和失败数量；不要仅依赖文件名判断供应商。导入后仍需验证凭证有效性。

## 图片与代理

- 401：检查账号凭证或调用方密钥，不反复重试失效账号。
- 429：等待上游恢复时间，减少并发，不把限流误判为账号失效。
- 403：核对代理出口及可选外部清障服务；不默认关闭 TLS 校验。
- 文件链接错误：设置 `GO_PUBLIC_BASE_URL`，不要信任未经清洗的转发头。
- 队列停滞：检查 `docker compose --profile images ps` 和对应日志，确认 Redis 挂载、内部调度密钥及鉴权文件。

## 升级后启动失败

核对 `data/config.json`、认证环境变量、旧覆盖文件和 UID/GID。不要清空数据目录来排错；保留失败日志后按 [回退步骤](MIGRATION.md) 处理。
